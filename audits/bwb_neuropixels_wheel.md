# Audit: bwb_neuropixels_wheel (BrainWideBench Neuropixels-to-wheel)

- [ ] **Published SOTA on the exact split.** The SOTA number on exactly this split (sessions, time bins, metric), with code and commit. Value: 0.362 (POYO+, wheel-speed R² clipped at 0, mean over the 29 evaluation sessions, ±0.001 SEM over 5 finetuning seeds). Source: Andre et al. 2026, arXiv 2609.22064v1, Table 1 (p. 8). Rerun: FILL. Gap: FILL
- [x] **Temporal leakage between neighbouring time bins.** Are dev and test bins interleaved within a session, so autocorrelation leaks? Required gap or block split: none needed beyond the benchmark's own. Finding: TS1 splits each evaluation session causally in trial order, not interleaved: first 40% of trials train, next 20% validation, last 40% test, with a 20 s gap between adjacent splits; the last-40% test split is enforced. Evidence: arXiv 2609.22064v1 Section 3.2 "TS1: Evaluation Setup" (pp. 5–6), Appendix C.2 and Figure A5 (pp. 28–29), Appendix D.1 "Enforced" (p. 33). Spec change: dev is the first 60% of trials (train and validation), test the last 40%, taken from the benchmark's split intervals with their 20 s gaps; recorded in `contamination.split_provenance`.
- [x] **Leakage between sessions.** Do sessions from the same animal or probe insertion appear in both dev and test? Finding: no animal is shared between the pretraining set (126 mice, 423 sessions) and the evaluation set (13 mice, 29 sessions). Within the evaluation set, every session, and so every evaluation mouse and probe insertion, appears in both dev and test by design, because the split is temporal within each session; the task measures generalization forward in time within sessions of unseen animals. Evidence: Section 3.1 (p. 5), Appendix C.1 and Figure A2 (pp. 26–27). Spec change: `contamination.split_provenance` states the animal-level split and the within-session split; the `poyo_plus` tool must be a checkpoint pretrained on the 423 pretraining sessions only (open in `tools.trained_models[0].interface`).
- [x] **Paper vs code: wheel anti-alias filter.** The paper says continuous behaviour, the 1 kHz wheel included, was low-pass filtered before downsampling with an 8th-order zero-phase Butterworth filter at 80% of the target Nyquist frequency (arXiv 2609.22064v1 Appendix A, "Signal Resampling and Anti-Aliasing Filtering", p. 24). The pipeline code instead decimates the wheel with `scipy.signal.decimate` and its default FIR filter, 10× then 2× (ibl-bwb @ 6fbd666, `ibl_brain_wide_bench_2026/pipeline.py:1045` and `:1086-1087`, `ibl_brain_wide_bench_2026/utils.py:14` and `:213-227`). Finding: the data follow the code. The staged data are the benchmark's processed build, which the benchmark's TS1 loader reads (docs/DATA.md); it was not recomputed here. Spec change: none.
- [x] **Paper vs code: trial exclusions.** The paper lists two exclusions: a missing trial event, and a reaction time (stimulus onset to first wheel movement) over 10 s (Appendix A.4, pp. 22-23). The code also drops trials with a negative reaction time (movement before stimulus onset) and no-choice trials (`ibl_brain_wide_bench_2026/pipeline.py:1180-1201`, applied at `:1236`). Finding: the data follow the code, so these trials are in neither dev nor test. Spec change: none.
